01 / EXPLICACIÓN

Dos prácticas que se complementan

Una ayuda a construir el comportamiento esperado; la otra evalúa la fuerza de los casos de prueba.

DESARROLLO

TDD

Test-Driven Development, o desarrollo guiado por pruebas, consiste en escribir una prueba antes del código que debe hacerla pasar.

  1. REDEscribe una prueba y confirma que falla.
  2. GREENImplementa lo mínimo para pasar.
  3. REFACTORMejora el diseño conservando las pruebas verdes.

Se repite en ciclos pequeños. Primero se define el comportamiento observable.

EVALUACIÓN

Mutation Testing

Práctica que introduce cambios pequeños y deliberados (mutantes) en el código para verificar si la suite de pruebas los detecta.

  1. MUTARCambia una operación o condición.
  2. EJECUTARCorre la misma suite contra el mutante.
  3. ANALIZARFallo = muerto; pasa = sobrevivió.

Un mutante sobreviviente puede revelar una aserción ausente, débil o un requisito no cubierto.

02 / USO

¿Cuándo conviene?

TDD es útil al implementar reglas de negocio, lógica con límites y funcionalidades que deben evolucionar con seguridad. Mutation Testing conviene cuando ya existe una suite automatizada y se quiere encontrar pruebas que pasan sin verificar lo importante.

Es más efectivo en unidades pequeñas y deterministas. En interfaces, infraestructura o código generado, el costo puede superar el valor.

Beneficios

  • Especifica el comportamiento antes de implementar.
  • Da feedback rápido y facilita refactorizar.
  • Expone aserciones débiles y huecos de pruebas.
  • Puede priorizar dónde fortalecer la suite.

Costos y límites

  • Exige disciplina y tiempo inicial.
  • Una mala prueba primero puede fijar un diseño incorrecto.
  • Muchos mutantes elevan el tiempo de ejecución.
  • El puntaje no demuestra ausencia de defectos ni reemplaza revisión.
  • Mutantes equivalentes pueden sobrevivir sin representar un error real.

04 / CONCLUSIÓN

Las pruebas también necesitan pruebas

TDD ayuda a desarrollar por incrementos pequeños y a expresar el resultado esperado. Mutation Testing plantea una pregunta complementaria: si introducimos un error sencillo, ¿la suite lo descubre? Combinar ambas técnicas aumenta la confianza en la retroalimentación, aunque la calidad final depende de requisitos claros, casos representativos y criterio técnico.
